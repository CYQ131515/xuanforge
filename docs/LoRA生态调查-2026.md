# 2026 LoRA 生态调查简报

> 调研快照：**2026-10-23** ｜ 面向「玄炉 XUANFORGE」产品原型
> 口径：可二次训练（LoRA / 轻量微调）的开源或开放权重模型，覆盖图像、视频、音频、语言四大模态。
> 说明：本文区分三类信息 —— ① **官方文档/模型卡事实**；② **训练器示例参数**；③ **社区口碑与第三方估计**。第 ③ 类仅供选型参考，不是基准测试。

---

## 0. 十句话结论

1. **LoRA 已经是「一个模型一个适配器」的标准件**：2026 年几乎所有新开源基座（FLUX.3 Klein、Qwen-Image 2.1、Z-Image、Krea 2、Wan 2.2、LTX-2.5、MiniMax H3、ACE-Step 1.5）都在发布时或数周内被主流训练器收编。
2. **图像仍是主战场，但格局已经从 SDXL/FLUX 两强变成「四梯队」**：FLUX 系（写实/风格上限）、Qwen-Image 系（中文文字/编辑/RGBA）、Z-Image（单卡性价比）、Krea/Anima/Chroma 等垂直审美与二次元线，再加上仍最稳的 SDXL 存量生态。
3. **「训 LoRA」和「训得好」是两件事**：官方示例里 rank、alpha、LR、optimizer、timestep shift 是一整套配方；单改一个数，效果可能完全跑偏。
4. **视频 LoRA 的门槛在 2026 年明显下降**：Wan 2.2 5B / LTX 低显存档 / H3 短片段已经能在 16–32G 显卡上跑通；Wan 2.2 是开源视频 LoRA 的第一选择。
5. **音频出现真正的 LoRA 生态**：ACE-Step 1.5 官方放出 LoRA 训练代码与 Lyric2Vocal / Text2Samples / RapMachine / StemGen（ControlNet-LoRA）样例；声音克隆则仍以 GPT-SoVITS 这类「少样本微调」为主。
6. **语言模型的 LoRA 工具链最成熟**：LLaMA-Factory 覆盖 100+ LLM，Qwen3 / Llama 4 / GLM / GPT-OSS / DeepSeek 蒸馏版都能单卡 QLoRA。
7. **社区平台两极分化**：Civitai 存量与全球覆盖第一，LiblibAI 在国内速度与国风素材深度上远超；两边都在提供云端训练，把「炼丹」做成 SaaS。
8. **最大的浪费不是算力，是配方与数据**：用推理量化版权重训练、混用不同世代的模型、给所有图同一句标注、用静帧教运动——这四类错误最常见。
9. **产品机会在「编排层」而不是「训练层」**：模型选择、配方预设、显存守卫、数据体检、一键导出到 ComfyUI、许可提示——这些是现有工具链最缺的部分。
10. **许可是独立问题**：基座许可、数据权利、导出 Adapter 的许可三件事必须分开看；真人形象/音色还需要额外授权。

## 2. 「效果」怎么理解

### 2.1 一份不装腔的对照

社区里最常见的选型问题不是「哪个最强」，而是「我要练什么」。按目标给建议：

| 你想练的东西 | 首选 | 次选 | 理由 |
|---|---|---|---|
| 真人/产品写实风 | FLUX.3 Klein / FLUX.2 | Krea 2 RAW | 细节与质感上限高，官方 LoRA 指引明确 |
| 中文文字、海报、电商图 | Qwen-Image 2.1 | Qwen-Image 2512 / Ideogram 4 | 中文字形与排版是公开模型里最强的一档；2.1 还带 RGBA |
| 二次元角色 | Anima / SDXL（Pony、Illustrious、NoobAI） | FLUX.3 Klein | Anima 有专用训练入口；SDXL 存量角色 LoRA 最多 |
| 单卡、低成本、快速迭代 | Z-Image Base 6B | SDXL | 16G 可跑，Musubi 示例完整 |
| 商用友好、许可干净 | Chroma1-Base（Apache-2.0）/ SDXL | Wan、ACE-Step（Apache-2.0） | 许可比效果更早决定能不能商用 |
| 视频镜头运动 | Wan 2.2 A14B | LTX-2.5 / Wan 2.2 5B | 生态、工具、示例最全 |
| 有声短视频 | MiniMax H3 | — | 音视频联合生成，但配方最复杂 |
| 曲风 / 歌声 | ACE-Step 1.5 XL | YuE2 | 官方 LoRA 训练代码是决定性优势 |
| 特定人声音色 | GPT-SoVITS | CosyVoice 3 / F5-TTS | 1 分钟素材即可，中文效果稳 |
| 领域 LLM / 角色扮演 | Qwen3-8B / 14B | Phi-4、Gemma 3、GPT-OSS 20B | 单卡 QLoRA 可训，中文语料友好 |

### 2.2 为什么没有「跑分」

- LoRA 的效果高度依赖**数据集、标注、分辨率、训练器版本**，同一个基座的两次训练可能差异巨大；跨模型的 LoRA 更不可直接对比。
- 公开榜单测的是**基座**，不是某个 LoRA；LoRA 社区（Civitai / Liblib）的「点赞」也不是质量指标。
- 因此本简报只给**定位与配方**，并在产品里把评分标注为「社区口碑的编辑化总结，非基准测试」。

### 2.3 平台与效果的关系

- **Civitai**：全球最大，LoRA 存量与风格覆盖第一（第三方估计 150k+ 模型 / 80k+ LoRA）；写实、西方奇幻、NSFW 类目更深。
- **LiblibAI**：国内最大（第三方估计 120k+ 模型 / 45k+ LoRA）；**水墨、仙侠、汉服、国风建筑、中文书法**等类目比海外站深 5–20 倍（第三方对比口径）。
- **Hugging Face / ModelScope**：基座与训练器的官方发布地，找「官方推荐参数」的第一站。
- 平台数据会变，且第三方估计口径不一；产品中应标注「数据截至日期」。

## 3. 训练方法与配方

### 3.1 低秩方法选型

| 方法 | 一句话 | 适合 |
|---|---|---|
| **LoRA** | 冻结基座，训练低秩旁路 | 默认之选；生态最广 |
| **LoHa** | Hadamard 积分解，表达力更强 | 风格、构图 |
| **LoKr** | Kronecker 分解，参数更省 | 省显存；工具支持有限 |
| **DoRA** | 幅度 + 方向解耦，低 rank 更接近全量微调 | 低 rank 任务；训练略慢 |
| **PiSSA** | SVD 主成分初始化 | 快速收敛；LLaMA-Factory 内置 |

### 3.2 起手参数（来自官方示例 / 社区实践）

| 模型族 | rank / alpha | LR | 其他关键项 |
|---|---|---|---|
| SDXL / Pony / Illustrious / NoobAI | 16–32 / = rank | 1e-4（UNet） | 冻结 TE；1024 分桶；NoobAI 注意 eps/v-pred |
| Anima | 8 / 1 | 1e-4 | AdamW8bit、bf16；只训 DiT |
| Z-Image Base | 32 | 1e-4 | shift 2.0、AdamW8bit |
| Qwen-Image（原版） | 16 | 5e-5 | shift 2.2；2.1 用其自身文档 |
| FLUX.1-dev | 16 / 16 | 1e-4 | batch 1、2000 步、512/768/1024 分桶 |
| FLUX.3 Klein Base | 32 | 官方未给固定值（沿 AI Toolkit 示例） | Base 版、prompt upsampler |
| Krea 2 RAW | 32 / 32 | 1e-4 | bf16；shift 2.5@1024 或 `krea2_shift` |
| Wan 2.1 / 2.2 | 32 | **2e-4** | shift 3.0；2.2 区分双专家 timestep |
| LTX-2.5 低显存档 | 16 / 16 | 1e-4 | batch 1、2000 步、INT8 + checkpointing |
| MiniMax H3 | 16 / 16（Musubi）或 8/8（Fizgig Fast） | 1e-4 固定 / 自适应 | 必须选择完整 loss 路线 |
| ACE-Step 1.5 XL | 16–32 | 1e-4 | 20–50 epoch（社区实践） |
| GPT-SoVITS | —（微调） | 8e-5 / 1e-4 | ≥1 分钟干净人声、8–15 epoch |
| LLM（QLoRA） | 16–64 / 2×rank | 1e-4（LoRA）/ 2e-4（QLoRA） | 1–3 epoch；留同分布验证集 |

### 3.3 数据与标注

- 一个目标：人 / 风格 / 产品 / 运动，只选一个。
- 20–50 张清晰素材足以起步；重复图不等于信息量。
- 去重、去水印、去压缩伪影、去矛盾身份；多角度、多光照、多背景。
- 标注：不变的特征写进 caption；变化的（服装、背景、动作）留给提示词。
- 视频按镜头边界切，保留连贯运动；静帧教不会运动。
- 验证集必须真正不同（不要把同一视频的相邻帧分到两边）。
- 记录：模型 revision、训练器 commit、标注规范、配置、随机种子。

| **ms-swift** | CLI + WebUI | 全模态 | 国内网络与魔搭生态 | 文档偏工程 |
| **ComfyUI** | 节点 | 推理 + 训练节点 | 推理事实标准；LoRA 测试工作流丰富 | 不是训练主力 |

## 5. 常见坑（按踩坑成本排序）

1. **用推理量化版训练**：fp8/GGUF 适合出图，不适合当基座。
2. **混模型世代**：FLUX.1 / 2 / 3、Qwen-Image 与 2.1 的键名、缓存、shift 都不同；加载不报错 ≠ 训对了。
3. **给所有图同一句标注**：触发词会吞掉一切。
4. **用静帧教运动**：视频 LoRA 需要连贯片段。
5. **相邻帧分进训练与验证**：记住 ≠ 泛化。
6. **照抄别人的 LR 与 shift**：rank/alpha/LR/optimizer/shift 是一套配方。
7. **环境与缓存不锁版本**：换版本先重算缓存。
8. **忽略许可与肖像权**：基座、数据、导出 Adapter、真人形象/音色是四个独立问题。

## 6. 对「玄炉」产品的建议

1. **模型谱 + 配方库**：把「哪个模型、用哪个训练器、什么参数」做成结构化数据，而不是散落在博客里。
2. **显存守卫**：训练前按模型/rank/batch/fp8/换块估算显存与耗时，超过阈值直接拦截或建议降档。
3. **数据体检**：重复检测、分辨率统计、标注覆盖率、验证集隔离检查——比多训 200 步更有价值。
4. **配方版本化**：一条配方 = 模型 revision + 训练器 commit + 参数 + 数据指纹；支持一键复现与对比。
5. **多工具编排**：图像走 ai-toolkit/musubi，LLM 走 LLaMA-Factory，音频走官方脚本——做「调度层」而不是重写训练器。
6. **导出即用**：直接产出 ComfyUI 可读的 LoRA，并附带触发词、推荐权重、样图与许可说明。
7. **云端/本地双模式**：本地跑不动时一键推到云 GPU；云端结果回流到丹房。
8. **许可提示**：在模型选择处直接展示基座许可与「能否商用」，避免训练完才发现不能用。
